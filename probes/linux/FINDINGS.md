# Linux platform exploration findings (sub-phase 3.0)

The evidence ledger sub-phase 3.0 requires. Every row maps one experiment to observed behavior and a doc-alignment verdict, and every row names the client stack that produced it and the scope its conclusion carries. Rows are graded against `docs/phases.md` Phase 3.

Probe scripts and raw captures are development aids kept outside the repository, so the `probe` cell names the probe area and step rather than a committed path. The `observed` cell quotes the capture field values the conclusion rests on.

## How to read a row

| column | meaning |
| --- | --- |
| `id` | stable row id (`L<area>-<n>`), cited by phases.md hunks and the contradictions index at the bottom |
| `probe` | the probe area and step that produced the row |
| `stack` | `dbus` = raw D-Bus via Gio, the product-relevant stack; `gi-atspi` = libatspi convenience reads; `tool` = external tools such as xdotool, xprop, xclip. Combinations are joined by " + " |
| `scope` | `api-contract` = product-wide, holds for any conforming AT-SPI client. `app` = specific to the measured application and version. `box` = specific to this environment. Downstream sub-phases read this column to know what generalizes |
| `phases.md expectation` | the sentence or claim in `docs/phases.md` the probe tested, or none |
| `observed` | the capture field values and measurements the verdict rests on |
| `verdict` | `CONFIRMS`, `CONTRADICTS`, `NEW-EDGE`, `DEFERRED` |
| `action` | what the finding obliges. `DEFERRED` rows carry `needs:` and `closure: 3.<n>`, the Phase 3 sub-phase that closes them |

Stack authority: where a `dbus` row and a `gi-atspi` or `tool` row disagree, the `dbus` row wins, because the Rust adapter speaks raw D-Bus.
