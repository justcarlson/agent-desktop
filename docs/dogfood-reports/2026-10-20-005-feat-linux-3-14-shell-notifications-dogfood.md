This branch adds GTK menu targeting and context work in `1dc87834` (aim actions through the popup), `6ff73be4` (live GTK4 menu bounds), and `65267ba0` (preserve popup context in live identity checks). Final-source menu interaction passed: F5 passed twice, including a GTK4 Calculator ref pick with a newly observed About dialog; R08 repeated that check once. R09 proved a closed menu ref becomes stale.

2. **Headed app actions and `focus-window` failed to focus (high; confirmed).** The operator saw `ACTION_FAILED` and a suggestion to focus manually; `xdotool windowactivate` plus a click did not help. **Disposition: fixed in `6521c529` (`fix(linux): identify an open overview before requesting focus`).** Regression and inversion receipt: `system::focus_window::tests::overview::an_open_overview_is_the_cause_when_nothing_was_granted` (`overview-preflight`, mutation makes the test fail; restored run passes). Final-source natural-overview proof passed twice: refusal at 14/12 ms, Escape at 14/14 ms, and focus recovery at 75/77 ms.

3. **`wait --menu` and `wait --event` were unsupported (medium; confirmed).** **Disposition: owned by phase 3.11.** Linux wait/event parity is covered there; it is not an outstanding 3.14 fix.

4. **`launch` was unsupported on Linux (medium; confirmed).** **Disposition: owned by phase 3.9.** Linux launch behavior is covered there; this is not an outstanding 3.14 fix.

## Author-driven integration delta (separate from the original 12 findings)

These regressions were identified and fixed while integrating the 3.14 work. They are additional integration findings, not rewrites of the stranger's original 12-item report.

1. **Menu refs needed complete popup context and owner binding.** Commit `65267ba0` preserves raw popup context through live identity and owner resolution. Focused tests include `tree::live_read::menu_tests::menu_live_identity_uses_the_fresh_context_and_actual_live_object_path` and `tree::menu_resolve::tests::a_successful_menu_resolution_carries_its_owner_window`. Inversion cases `popup-live-context` and `popup-owner-binding` each fail under their targeted mutation and pass after byte-exact restoration. Label and unreadable-context coverage is also recorded in `popup-relation-label`, `popup-unreadable-label`, `popup-unreadable-role`, and `popup-unreadable-name`.

2. **Live GTK4 menu bounds must use the popup origin, never a managed-window decoy.** Fixed in `6ff73be4`. Unit regressions are `tree::live_read::popup_bounds_tests::bounds_via_uses_the_unique_popup_origin_and_never_the_managed_decoy` and `tree::live_read::popup_bounds_tests::an_absent_or_ambiguous_popup_origin_produces_no_bounds_without_fallback`. Inversion cases `gtk-popup-managed-decoy` and `gtk-popup-missing-origin-fallback` target those tests and have passing restored runs in the `b746ca87` inversion receipt; both tests also passed in the final `443db3d5` focused suite. `gtk4-popup-origin` additionally inverts `tree::node_position::tests::gtk4_menu_origin_selection_uses_the_popup_source`.

3. **Headed right-click must use physical delivery first.** Fixed in `443db3d5` (`fix(linux): honor pointer delivery for headed right-clicks`). Regression and inversion case are `actions::dispatch::tests::a_headed_right_click_uses_physical_delivery_before_semantic_delivery` / `headed-right-click-route`; the targeted mutation fails and byte-exact restoration passes. The final Chrome native-XQuery replacement passed twice under `314-chrome-native-xquery-443db3d5`: XTEST caused the native right-click effect and closed the existing popup, with Chrome's main frame and the same X11 client active. This is not a claim that a second menu opened; the test explicitly proves popup close and pointer effect, replacing the former semantic no-op and weak/manual oracle.

4. **Current-source end-to-end menu and pointer proofs.** F1–F5 and F7 each passed twice; F6's original delta rows failed twice because the Chrome probe used the wrong effect oracle, and are retained as historical failures in the raw delta artifacts under `~/ad-wt/314-delta-443db3d5/`. The independent native-XQuery replacement for F6 passed twice as described above. In addition, R01–R20 all passed once; F5 proved a real GTK4 Calculator ref pick opened a new About dialog twice; R08 repeated it once. The separate GTK4 raw-pointer proof passed twice in the replacement artifacts under `~/ad-wt/314-replacement-proofs-443db3d5/`: the live menu geometry was 676,400,92,30 against independent X11 root geometry 655,380,110,76; a click at 722,415 emitted exactly one `ITEM_ACTIVATED`, closed the menu, and left the app button present. Raw pointer evidence proves this GTK4 pointer path; F5 and R08 prove the ref-based route.
