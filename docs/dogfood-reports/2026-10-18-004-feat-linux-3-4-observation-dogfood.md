## Findings

| Id | Severity | Finding | Disposition |
|----|----------|---------|-------------|
| F1 | high | `snapshot` in the default namespace answered `INTERNAL` "private file parent is accessible by group or other users", with no directory named and no recovery. | Accepted for the cause, owner item for the wording. The cause was the operator's environment, which had pre-created the state root group-writable (0775); a root the tool creates is 0700 and works, measured in both directions. The error text is a core change, written as an owner item in the Phase 3 introduction of `docs/phases.md`: "The private-file-parent error (`crates/core/src/private_file_parent.rs:22-26`) names no directory and gives no `chmod 700 <dir>` suggestion". |
| F2 | high | `snapshot --root <ref>`, `get` and `is` answer `PLATFORM_NOT_SUPPORTED` on every ref. | Owned elsewhere. `docs/phases.md` §3.5 exit criteria now end: "`snapshot --root @ref`, `get` and `is` run end to end on GNOME apps". |
| F3 | medium | Only the process name works for `--app` (`gnome-calculator`, `nautilus`, `gnome-text-editor`); `Calculator`, `Files` and `Text Editor` do not, `list-apps --app calc` substring-matches while `snapshot --app calc` does not, and the suggestion talks about `.exe` on Windows. | Owned elsewhere, in three places. `docs/phases.md` §3.9 scope: "`desktop_entry.rs` also reads `Name`; `--app` accepts it as a match alias for a process whose exe basename equals the entry's Exec program basename; the listed name is unchanged (ledger L19-1)". §3.13 Linux skill: "`--app` takes the process name `list-apps` shows (gnome-calculator, nautilus, gnome-text-editor) or the registry name (org.gnome.Nautilus); display names such as Calculator or Files are accepted only once the desktop-entry alias lands". The Windows-flavoured core suggestion (`crates/core/src/app_lookup.rs:80-82`) is an owner item in the Phase 3 introduction. |
| F4 | medium | `list-windows --app Calculator` returned `ok:true` with `[]`, while `list-surfaces` and `snapshot` returned `APP_NOT_FOUND` for the same name. | Fixed here. A scoped `list-windows` whose name matches no registry application and no running process answers `APP_NOT_FOUND` with a suggestion naming `list-apps` (the answer macOS gives). A registered application with no windows and a process that is running off the bus keep `[]` (ledger L20-2). Tests `an_unknown_name_is_app_not_found_suggesting_list_apps`, `a_registered_app_without_windows_is_not_an_unknown_name` and `a_bus_less_process_keeps_the_empty_list` in `crates/linux/src/system/unresponsive_tests.rs`. Inverted: with the check short-circuited to success, `an_unknown_name_is_app_not_found_suggesting_list_apps` failed and the other two kept passing, as they should. `snapshot` and `list-surfaces` already answered `APP_NOT_FOUND`, so the three now agree; no separate consistency test was added because they reach the registry by different paths. |
| F5 | medium | `--skeleton` changed nothing on Calculator: 4829 bytes, depth 15, no `children_count`. | Accepted for the behaviour: Calculator's nesting is 34 empty layout wrappers that the walk skips by design, and `--skeleton` on Text Editor does emit `children_count` (J7). The wording is owned by §3.13 and a core-skill owner item (see F6). |
| F6 | medium | `--max-depth 2` returned a 17-level tree and `--max-depth 1` a 15-level one. | Owned elsewhere. `--max-depth` and `--skeleton` count semantic levels; empty layout wrappers do not count, so output nesting can exceed the number. Written into `docs/phases.md` §3.13 (Linux skill) and as an owner item for the core skill in the Phase 3 introduction. |
| F7 | high | `find` with at least one match and no `--count` answers `PLATFORM_NOT_SUPPORTED` ("resolve_locator_anchor"). | Accepted here, owned by 3.5 (ledger L20-3): `find` is live with the resolver, which §3.5 scope already lists as `resolve_locator_anchor` and `resolve_query`. |
| F8 | medium | Unsupported-feature errors name internal methods and carry `retry: safe`. | Owner item in the Phase 3 introduction: "Trait-default `not_supported()` errors name internal methods ... and carry `retry: safe` (`crates/core/src/adapter_error.rs:137-146`)". The list of unavailable commands is owned by §3.13 (F9). |
| F9 | low | `skills get platform` fails with `retry: safe`, and no text lists what Linux lacks, so an agent discovers it by failure. | Owned elsewhere. `docs/phases.md` §3.13: "the Linux skill lists the commands that are not available yet, so an agent does not discover them by failure". The `skills get platform` Linux arm was already an owner item. |
| F10 | low | `--compact` is a no-op on top of `-i` and leaves the empty wrappers. | Owner item (affects every platform): "`--compact` is a no-op on every platform whenever bounds are collected, because `is_collapsible` (`crates/core/src/ref_alloc.rs:94-123`) runs before the bounds strip (~277-283)"; it should be evaluated after the strip, or ignore bounds when `include_bounds` is false. |
| F11 | low | Output differs from documented shapes: (1) `children_count` nodes emit `"name":null`; (2) the Calculator display shows no value; (3) `list-apps` lacks `bundle_id` and adds `process_instance`, and nodes add `available_actions`. | (1) and (2) accepted: no `"name":null` appears in the raw JSON, and the display value is empty at launch and shown once text exists, both measured. (3) Owned elsewhere: §3.13 documents that `bundle_id` is omitted on Linux, and documenting `available_actions` and `process_instance` is an owner item for the core skill in the Phase 3 introduction. |
| F12 | low | The skill says observation commands carry no `disposition`, but their errors do. | Owner item: the core skill (`skills/agent-desktop/SKILL.md:60`) contradicts core, which attaches one. |
| F13 | low | Window ids are 34 to 68 characters with a per-session GUID. | Owned elsewhere. `docs/phases.md` §3.13: "window ids are opaque addresses (34-70 characters) valid for the life of the window's process; re-run `list-windows` after a restart". |
| F14 | low | Firefox (snap) and Chrome never appear in `list-apps` or `list-windows`; `wait --window` times out at 60 s. | Accepted. The Firefox snap wrapper cannot start in a private session (ledger L16-15), so it was never on the bus, and Chrome is listed as `chrome`. A running process that is off the bus already gets the no-connection diagnostic from `list-apps --app` and `snapshot --app`. |
| F15 | info | The `SNAPSHOT_NOT_FOUND` suggestion is a long FFI-flavoured paragraph, and an unknown `--role` lists no valid roles. | Owner item: the suggestion text (`crates/core/src/adapter_error.rs:80,217`, `crates/core/src/actionability/live.rs:165`) and the role validation (`crates/core/src/live_locator/validate.rs:46`) are core. |
