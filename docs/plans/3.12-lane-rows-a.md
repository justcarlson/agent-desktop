Measured on the Linux box through `scripts/remote-linux.sh` from this worktree.
Integration renumbers these into `L34-n` at merge; ids are lane-local.

|----|-------|-------|-------|-------------|----------|---------|--------|
| A-1 | group signal cancels a running session | private-session.sh | SIGINT/SIGTERM/SIGHUP to the session process group during a `sleep 300` payload | signal forwards to the payload group, conventional status, no member, no runtime dir | 130/143/129 returned, zero `/proc` members, dir removed for all three signals | confirmed | none |
| A-2 | SIGINT ignored on entry can never be re-trapped | private-session.sh + runner/session.py | payload launched via non-interactive `&` (POSIX ignores INT/QUIT in background children) | the wrapper's INT trap fires | trap never armed: SIG_IGN survives exec and POSIX forbids re-trapping | confirmed | session.py resets SIGINT to SIG_DFL in the spawned child (preexec_fn) so an inherited ignore never reaches the wrapper; the live SIGINT check launches the same way the harness does |
| A-3 | /proc/PID/environ is an exec-time snapshot | private-session.sh | reading the wrapper's own environ for XDG_RUNTIME_DIR | the export shows | exports made after exec never appear; only children exec'd with the variable carry it | confirmed | membership and runtime-dir discovery read children/member environs, never the wrapper's own |
| A-4 | setsid'd inner shell escapes the group signal | private-mutter-shell.sh | gnome-shell --x11 started via setsid, TERM to the session group | the shell survives the group signal and is still reclaimed | gnome-shell joins the member set under the runtime dir, the membership sweep removes it after cancel | confirmed | teardown sweeps by runtime-dir membership, not by the tracked child list |
| A-5 | bus-activated Terminal maps on the mutter display | private-mutter-shell.sh | org.gnome.Terminal Activate over the private bus | the window maps on the mutter Xvfb (:150+) not the outer display (:100) | xdotool finds the window on the mutter display after the activation-environment DISPLAY push | confirmed | push DISPLAY (and XAUTHORITY when set) into the activation environment before the shell starts |

| A-7 | the release-wait payload pollutes the owned set | runner/session.py | `sleep 0.2` polling loop inside the payload | baseline member set stays stable across reads | each iteration is a transient member; the set flapped between evaluations | confirmed | the loop waits on a private fifo with `read -t` (a bash builtin), spawning no processes |
