## Retirements and replacements

- Default timeout, unscoped window-opened quiet, scoped window close,
  second-position Mutter GTK4 gesture and maximize retry: private
  `tracker-extract` left the process baseline. Remove the environment-dependent
  checks; retain fake timeout, event, focus, geometry and state contracts.
- Unscoped window close: the single diagnostic rerun reached the corrected
  batch transport, but the Close target's bounds stayed unavailable and the
  product honestly refused delivery. The private frame/transport fake remains.
- Mutter app-launched and window-event cells, and Qt raw click: raw bus
  name/frame reads timed out before product commands. No timeout tuning or
  product fix is inferred.
- Mutter Qt headed click, scroll and menus: the launcher attributed both
  `mutter-x11-frames` and the Qt owner before any product command. Keep the
  deterministic log/menu contracts, retire the live launch cells.
- VS Code: three launch attempts produced no attributable window within the
  existing 35-second observed-window deadline. Keep frame-generation checks.
- GTK3 Edit target: no role-35 Edit on the installed Terminal. Do not substitute
  a guessed node. Motion-only gesture attempts lacked an app effect oracle.
- Wayland clipboard: successful-content fixtures required a keyboard seat
  absent from this headless session. The attempted refusal checks also lacked
  an observable foreign offer state; retire them rather than count reader
  errors as proof of an empty clipboard. A fake contract rejects that false
  pass. Image-file cleanup acquired a process only after all clipboard/proc
  restoration reads; retire that environment-dependent image case.
- Correct the deterministic batch `ref`/`ref_id` typo and zero-timeout
  expectation; portable tests fail if either correction is removed.

No failed test was rerun more than once. No whole-harness box run was made.
